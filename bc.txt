1. MÔ TẢ CHUNG
--------------
ESP32_Demo là một dự án IoT hoàn chỉnh sử dụng vi điều khiển ESP32 để điều khiển 
bình nóng lạnh thông minh thông qua giao thức MQTT. Hệ thống cho phép:
- Bật/tắt thiết bị từ xa qua mạng
- Đặt lịch bật/tắt tự động theo thời gian
- Giám sát trạng thái thiết bị realtime
- Hỗ trợ cả Local MQTT Server và Cloud Server (HiveMQ)

2. KIẾN TRÚC HỆ THỐNG
---------------------
Dự án bao gồm 3 thành phần chính:

┌─────────────────────┐         ┌──────────────────┐         ┌─────────────────┐
│   ESP32 Hardware    │ ◄─────► │   MQTT Broker    │ ◄─────► │  Web Dashboard  │
│  + Relay Module     │  MQTT   │  (Local/Cloud)   │  HTTP   │   (Frontend)    │
│  + RTC DS1307       │         │                  │         │                 │
└─────────────────────┘         └──────────────────┘         └─────────────────┘

Luồng hoạt động:
1. ESP32 kết nối WiFi và MQTT Broker
2. ESP32 subscribe các topic điều khiển
3. Web Dashboard gửi lệnh qua HTTP API
4. Backend publish message lên MQTT
5. ESP32 nhận lệnh và điều khiển relay
6. ESP32 gửi trạng thái ngược lại

A. PHẦN CỨNG (ESP32 HARDWARE)
==============================

1. Vi điều khiển: ESP32 DevKit V1
   - Board: esp32doit-devkit-v1
   - Framework: Arduino
   - Serial Monitor Speed: 115200 baud
   - Upload Port: COM8
   - WiFi: 2.4GHz only (không hỗ trợ 5GHz)

2. Module kết nối:
   
   a) Relay Module (1 kênh):
      - VCC   → ESP32 5V
      - GND   → ESP32 GND.1
      - IN    → ESP32 GPIO 23
      Chức năng: Điều khiển bật/tắt bình nóng lạnh

   b) RTC DS1307 (Real-Time Clock):
      - 5V    → ESP32 5V
      - GND   → ESP32 GND.2
      - SCL   → ESP32 GPIO 22 (I2C Clock)
      - SDA   → ESP32 GPIO 21 (I2C Data)
      Chức năng: Lưu trữ thời gian thực, hỗ trợ đặt lịch

3. Thư viện phụ thuộc:
   - RTClib@^2.1.1 (Adafruit): Giao tiếp RTC DS1307
   - PubSubClient@^2.8: MQTT client cho ESP32

4. Các chân GPIO sử dụng:
   - GPIO 23: Điều khiển relay (OUTPUT)
   - GPIO 22: I2C SCL (RTC)
   - GPIO 21: I2C SDA (RTC)
   - TX/RX: Serial Monitor

2. Cấu hình MQTT:

   b) Cloud Server Mode (USE_LOCAL_SERVER = false):
      - Server: beef441362934e51ba18727f8ae7f97b.s1.eu.hivemq.cloud
      - Port: 8883 (TLS encrypted)
      - Username: admin
      - Password: Admin123

3. Topics MQTT:
   
   Subscribe (nhận lệnh):
   - nha_toi/binh_nong_lanh/lenh
     Messages: "ON" hoặc "OFF"
     
   - nha_toi/binh_nong_lanh/dat_lich_bat
     Format: "HH:MM" (VD: "14:30")
     
   - nha_toi/binh_nong_lanh/dat_lich_tat
     Format: "HH:MM" (VD: "15:00")
   
   Publish (gửi trạng thái):
   - nha_toi/binh_nong_lanh/trang_thai
     Messages: "DA BAT", "DA TAT", "DA BAT THEO LICH", 
               "DA TAT THEO LICH", "DA DAT LICH BAT: HH:MM"

4. Chức năng chính:

   a) callback(): Xử lý message MQTT nhận được
      - Bật/tắt relay theo lệnh ON/OFF
      - Lưu lịch bật/tắt từ message
      - Publish trạng thái sau khi thực hiện

   b) reconnect(): Tự động kết nối lại MQTT khi mất kết nối
      - Tạo Client ID ngẫu nhiên
      - Subscribe lại tất cả topics
      - Retry sau 5 giây nếu thất bại

   c) checkSchedule(): Kiểm tra và thực thi lịch hẹn
      - So sánh thời gian hiện tại với lịch đặt
      - Tự động bật/tắt relay khi đến giờ
      - Chỉ trigger 1 lần cho mỗi phút
      - Hỗ trợ cả RTC và NTP time

   d) setup(): Khởi tạo hệ thống
      - Khởi tạo Serial, GPIO, RTC
      - Kết nối WiFi
      - Đồng bộ thời gian từ NTP (pool.ntp.org, GMT+7)
      - Cập nhật thời gian cho RTC nếu có
      - Kết nối MQTT Server

   e) loop(): Vòng lặp chính
      - Duy trì kết nối MQTT
      - Kiểm tra lịch hẹn liên tục
      - In thời gian hiện tại mỗi 5 giây

5. Xử lý thời gian:
   - NTP Server: pool.ntp.org
   - Timezone: GMT+7 (Việt Nam)
   - Fallback: Nếu không có RTC, dùng NTP
   - Update: RTC được cập nhật từ NTP khi ESP32 boot

A. LUỒNG HOẠT ĐỘNG MQTT SERVER (server.js)
===========================================

1. KHỞI ĐỘNG SERVER
-------------------
   
   Bước 1: Load Configuration
   ├─ Đọc file .env (dotenv.config())
   ├─ Load config:
   │  ├─ mqttPort = 1883
   │  ├─ wsPort = 8080
   │  ├─ username = "admin"
   │  ├─ password = "Admin123"
   │  ├─ enableLogging = true
   │  └─ logMessages = true
   └─ Khởi tạo Map() để lưu clients

   Bước 2: Setup Authentication Handler
   ├─ aedes.authenticate = (client, username, password, callback)
   ├─ Kiểm tra username === config.username
   ├─ Kiểm tra password.toString() === config.password
   ├─ Nếu đúng:
   │  ├─ Log: ✓ Client [clientId] authenticated
   │  └─ callback(null, true)
   └─ Nếu sai:
      ├─ Log: ✗ Client [clientId] authentication failed
      ├─ Tạo error với returnCode = 4 (Bad username or password)
      └─ callback(error, false)

   Bước 3: Setup Event Handlers
   
   a) aedes.on('client', handler):
      ├─ Khi client kết nối thành công
      ├─ Lấy timestamp hiện tại (vi-VN locale)
      ├─ Lưu vào Map: clients.set(client.id, { connectedAt: timestamp })
      ├─ Log: Client connected: [clientId]
      └─ Log: Total clients: [số lượng]
   
   b) aedes.on('clientDisconnect', handler):
      ├─ Khi client ngắt kết nối
      ├─ Xóa khỏi Map: clients.delete(client.id)
      ├─ Log: Client disconnected: [clientId]
      └─ Log: Total clients: [số lượng còn lại]
   
   c) aedes.on('subscribe', handler):
      ├─ Khi client subscribe topic
      ├─ Kiểm tra config.logSubscriptions
      ├─ Nếu true:
      │  ├─ Log: Client [clientId] subscribed:
      │  └─ Với mỗi subscription:
      │     └─ Log: - [topic] (QoS: [0/1/2])
   
   d) aedes.on('unsubscribe', handler):
      ├─ Khi client unsubscribe topic
      ├─ Kiểm tra config.logSubscriptions
      ├─ Nếu true:
      │  ├─ Log: Client [clientId] unsubscribed:
      │  └─ Với mỗi topic:
      │     └─ Log: - [topic]
   
   e) aedes.on('publish', handler):
      ├─ Khi có message được publish
      ├─ Kiểm tra config.logMessages && client exists
      ├─ Nếu true:
      │  ├─ Parse: message = packet.payload.toString()
      │  ├─ Log: Message published:
      │  ├─ Log: Client: [clientId]
      │  ├─ Log: Topic: [packet.topic]
      │  ├─ Log: Message: [message]
      │  └─ Log: QoS: [0/1/2], Retain: [true/false]
   
   f) aedes.on('clientError', handler):
      └─ Log: Client error [clientId]: [err.message]
   
   g) aedes.on('connectionError', handler):
      └─ Log: Connection error: [err.message]

   Bước 4: Start TCP Server (MQTT Protocol)
   ├─ mqttServer = net.createServer(aedes.handle)
   ├─ mqttServer.listen(1883, callback)
   ├─ Log startup banner:
   │  ├─ MQTT Server Started!
   │  ├─ MQTT Port: 1883
   │  ├─ WebSocket Port: 8080
   │  ├─ Authentication: Enabled
   │  └─ Username/Password info
   ├─ Hiển thị local IP addresses:
   │  ├─ Quét os.networkInterfaces()
   │  ├─ Lọc IPv4 không phải internal
   │  └─ Log tất cả IPs có thể kết nối
   └─ Log: Waiting for clients...

   Bước 5: Start WebSocket Server
   ├─ httpServer = http.createServer()
   ├─ ws.createServer({ server: httpServer }, aedes.handle)
   ├─ httpServer.listen(8080)
   └─ Log: WebSocket server ready on port 8080

   Bước 6: Setup Monitoring
   ├─ setInterval(30000ms):
   │  ├─ Kiểm tra clients.size > 0
   │  ├─ Log: Active clients: [số lượng]
   │  └─ Với mỗi client:
   │     └─ Log: - [clientId] (connected: [timestamp])
   └─ Lặp lại mỗi 30 giây

   Bước 7: Setup Graceful Shutdown
   ├─ process.on('SIGINT', handler):
   │  ├─ Log: Shutting down server...
   │  ├─ aedes.close(callback)
   │  ├─ Log: Server closed
   │  └─ process.exit(0)

2. XỬ LÝ KẾT NỐI TỪ ESP32
--------------------------

   Bước 1: ESP32 gửi CONNECT packet
   ├─ Chứa: clientId = "ESP32Client-XXXX"
   ├─ Chứa: username = "admin"
   └─ Chứa: password = "Admin123"

   Bước 2: Server nhận CONNECT
   ├─ Trigger: aedes.authenticate()
   ├─ Kiểm tra credentials
   └─ Nếu thành công:
      ├─ Log: Client [ESP32Client-XXXX] authenticated
      ├─ Trigger: aedes.on('client')
      ├─ Lưu client info vào Map
      ├─ Log: Client connected: ESP32Client-XXXX
      ├─ Log: Total clients: 1
      └─ Gửi CONNACK (code=0) về ESP32

   Bước 3: ESP32 gửi SUBSCRIBE packets
   ├─ Topic 1: "nha_toi/binh_nong_lanh/lenh"
   ├─ Topic 2: "nha_toi/binh_nong_lanh/dat_lich_bat"
   └─ Topic 3: "nha_toi/binh_nong_lanh/dat_lich_tat"

   Bước 4: Server xử lý SUBSCRIBE
   ├─ Trigger: aedes.on('subscribe')
   ├─ Log: Client [ESP32Client-XXXX] subscribed:
   ├─ Log: - nha_toi/binh_nong_lanh/lenh (QoS: 0)
   ├─ Log: - nha_toi/binh_nong_lanh/dat_lich_bat (QoS: 0)
   ├─ Log: - nha_toi/binh_nong_lanh/dat_lich_tat (QoS: 0)
   ├─ Lưu subscriptions vào Aedes internal state
   └─ Gửi SUBACK về ESP32

3. XỬ LÝ MESSAGE PUBLISH
-------------------------

   Kịch bản A: Backend publish → ESP32
   
   Bước 1: Backend gửi message
   ├─ Topic: "nha_toi/binh_nong_lanh/lenh"
   ├─ Payload: "ON"
   └─ QoS: 0

   Bước 2: Server nhận PUBLISH packet
   ├─ Trigger: aedes.on('publish')
   ├─ packet.topic = "nha_toi/binh_nong_lanh/lenh"
   ├─ packet.payload = Buffer("ON")
   ├─ packet.qos = 0
   ├─ Convert: message = packet.payload.toString() = "ON"
   ├─ Log: Message published:
   ├─ Log: Client: [backend-client-id]
   ├─ Log: Topic: nha_toi/binh_nong_lanh/lenh
   ├─ Log: Message: ON
   └─ Log: QoS: 0, Retain: false

   Bước 3: Server routing message
   ├─ Aedes kiểm tra subscriptions
   ├─ Tìm thấy: ESP32Client-XXXX subscribe topic này
   ├─ Forward PUBLISH packet đến ESP32
   └─ ESP32 nhận được message "ON"

   Kịch bản B: ESP32 publish → Backend
   
   Bước 1: ESP32 gửi trạng thái
   ├─ Topic: "nha_toi/binh_nong_lanh/trang_thai"
   ├─ Payload: "DA BAT"
   └─ QoS: 0

   Bước 2: Server nhận và log
   ├─ Trigger: aedes.on('publish')
   ├─ Log: Message published:
   ├─ Log: Client: ESP32Client-XXXX
   ├─ Log: Topic: nha_toi/binh_nong_lanh/trang_thai
   ├─ Log: Message: DA BAT
   └─ Log: QoS: 0, Retain: false

   Bước 3: Server routing
   ├─ Kiểm tra subscribers của topic này
   ├─ Tìm thấy: backend-client subscribe "nha_toi/binh_nong_lanh/trang_thai"
   ├─ Forward message đến Backend
   └─ Backend nhận được "DA BAT"

4. XỬ LÝ NGẮT KẾT NỐI
----------------------

   Bước 1: ESP32 mất WiFi hoặc gửi DISCONNECT
   └─ TCP connection closed

   Bước 2: Server phát hiện disconnect
   ├─ Trigger: aedes.on('clientDisconnect')
   ├─ clients.delete("ESP32Client-XXXX")
   ├─ Log: Client disconnected: ESP32Client-XXXX
   ├─ Log: Total clients: 0
   └─ Cleanup subscriptions và resources

   Bước 3: ESP32 reconnect
   ├─ ESP32 gửi CONNECT packet mới
   ├─ Server authenticate lại
   ├─ ESP32 subscribe lại tất cả topics
   └─ Hoạt động trở lại bình thường

1. KHỞI ĐỘNG HỆ THỐNG - setup()

   ├─ Nếu thành công:
   │  ├─ rtcAvailable = true
   │  └─ Log: "RTC da san sang!"
   └─ Nếu thất bại:
      ├─ rtcAvailable = false
      └─ Log: "CANH BAO: Khong tim thay RTC! Se dung thoi gian tu NTP..."

   Bước 3: Kết nối WiFi
   ├─ WiFi.begin(ssid="KNT", password="123456789")
   ├─ Loop while (WiFi.status() != WL_CONNECTED):
   │  ├─ delay(500)
   │  └─ Serial.print(".")
   ├─ Log: "WiFi da ket noi!"
   └─ Log: "IP address: [ESP32 IP]"

   Bước 4: Đồng bộ thời gian NTP
   ├─ configTime(gmtOffset_sec=25200, daylightOffset_sec=0, ntpServer="pool.ntp.org")
   ├─ Loop retry (max 10 lần):
   │  ├─ getLocalTime(&timeinfo)
   │  ├─ Nếu thất bại:
   │  │  ├─ Log: "Dang cho thoi gian tu NTP..."
   │  │  ├─ delay(1000)
   │  │  └─ retry++
   │  └─ Nếu thành công:
   │     └─ Break loop
   ├─ Nếu lấy được thời gian:
   │  ├─ Log: "Da dong bo thoi gian thanh cong!"
   │  ├─ Log: "Thoi gian hien tai: DD/MM/YYYY HH:MM:SS"
   │  ├─ Nếu rtcAvailable == true:
   │  │  ├─ rtc.adjust(DateTime(...từ NTP...))
   │  │  └─ Log: "Da cap nhat thoi gian cho RTC!"
   └─ Nếu thất bại:
      └─ Log: "CANH BAO: Khong the lay thoi gian tu NTP!"

   Bước 5: Setup MQTT Client
   ├─ Nếu USE_LOCAL_SERVER == false (Cloud):
   │  ├─ WiFiClientSecure *secureClient = new WiFiClientSecure()
   │  ├─ secureClient->setInsecure() // Bỏ qua verify cert
   │  └─ client.setClient(*secureClient)
   ├─ Nếu USE_LOCAL_SERVER == true (Local):
   │  └─ Dùng WiFiClient thường (espClient)
   ├─ client.setServer(mqtt_server="192.168.137.1", mqtt_port=1883)
   ├─ client.setCallback(callback) // Set message handler
   ├─ Log: "HE THONG DA SAN SANG!"
   ├─ Log: "Ket noi toi MQTT Server: 192.168.137.1"
   └─ Log: "Port: 1883"

2. VÒNG LẶP CHÍNH - loop()
---------------------------

   ┌─────────────────────────────────────────────────┐
   │  while(true) {                                  │
   │    1. Kiểm tra kết nối MQTT                    │
   │    2. Xử lý MQTT messages                      │
   │    3. Kiểm tra lịch hẹn                        │
   │    4. In thời gian (mỗi 5s)                    │
   │  }                                              │
   └─────────────────────────────────────────────────┘

   Chi tiết từng bước:

   Bước 1: Kiểm tra kết nối MQTT
   ├─ if (!client.connected())
   │  └─ Gọi reconnect()
   └─ else: Tiếp tục

   Bước 2: Xử lý MQTT messages
   ├─ client.loop()
   ├─ Hàm này:
   │  ├─ Đọc packets từ socket
   │  ├─ Parse MQTT messages
   │  ├─ Gọi callback() nếu nhận được PUBLISH
   │  ├─ Gửi PINGREQ/PINGRESP để keep-alive
   │  └─ Xử lý PUBACK, SUBACK, etc.
   └─ Non-blocking, return ngay

   Bước 3: Kiểm tra lịch hẹn
   ├─ Gọi checkSchedule()
   └─ (Chi tiết ở phần 5)

   Bước 4: Debug logging (mỗi 5 giây)
   ├─ static unsigned long lastPrint = 0
   ├─ if (millis() - lastPrint > 5000):
   │  ├─ Nếu rtcAvailable:
   │  │  ├─ DateTime now = rtc.now()
   │  │  └─ Log: "Thoi gian hien tai (RTC): HH:MM:SS"
   │  ├─ Else:
   │  │  ├─ getLocalTime(&timeinfo)
   │  │  └─ Log: "Thoi gian hien tai (NTP): HH:MM:SS"
   │  └─ lastPrint = millis()
   └─ Continue loop

3. KẾT NỐI MQTT - reconnect()
------------------------------

   ┌─────────────────────────────────────────────────┐
   │  while (!client.connected()) {                  │
   │    1. Tạo clientId ngẫu nhiên                  │
   │    2. Thử kết nối với credentials              │
   │    3. Nếu thành công: Subscribe topics         │
   │    4. Nếu thất bại: Chờ 5s và retry            │
   │  }                                              │
   └─────────────────────────────────────────────────┘

   Chi tiết:

   Bước 1: Tạo Client ID
   ├─ String clientId = "ESP32Client-"
   ├─ clientId += String(random(0xffff), HEX)
   └─ VD: "ESP32Client-A3F2"

   Bước 2: Thử kết nối
   ├─ client.connect(clientId.c_str(), mqtt_user="admin", mqtt_pass="Admin123")
   ├─ Hàm này:
   │  ├─ Mở TCP socket đến mqtt_server:mqtt_port
   │  ├─ Gửi CONNECT packet với credentials
   │  ├─ Đợi nhận CONNACK
   │  └─ Return true/false
   
   Bước 3: Nếu thành công (return true)
   ├─ client.subscribe("nha_toi/binh_nong_lanh/lenh")
   ├─ client.subscribe("nha_toi/binh_nong_lanh/dat_lich_bat")
   ├─ client.subscribe("nha_toi/binh_nong_lanh/dat_lich_tat")
   └─ Break while loop

   Bước 4: Nếu thất bại (return false)
   ├─ delay(5000) // Chờ 5 giây
   └─ Continue while loop (retry)

4. XỬ LÝ MESSAGE - callback()
------------------------------

   Function signature:
   void callback(char *topic, byte *payload, unsigned int length)

   Bước 1: Parse payload thành String
   ├─ String message = ""
   ├─ for (int i = 0; i < length; i++):
   │  └─ message += (char)payload[i]
   └─ VD: message = "ON"

   Case A: Topic = "nha_toi/binh_nong_lanh/lenh"
   ├─ if (message == "ON"):
   │  ├─ digitalWrite(relayPin=23, HIGH) // Bật relay
   │  └─ client.publish("nha_toi/binh_nong_lanh/trang_thai", "DA BAT")
   │     ├─ Tạo PUBLISH packet
   │     ├─ Gửi đến MQTT server
   │     └─ Server forward đến Backend
   ├─ else if (message == "OFF"):
   │  ├─ digitalWrite(relayPin=23, LOW) // Tắt relay
   │  └─ client.publish("nha_toi/binh_nong_lanh/trang_thai", "DA TAT")
   └─ Return

   Case B: Topic = "nha_toi/binh_nong_lanh/dat_lich_bat"
   ├─ VD: message = "14:30"
   ├─ int separatorIndex = message.indexOf(':')
   ├─ if (separatorIndex != -1):
   │  ├─ onHour = message.substring(0, separatorIndex).toInt() // = 14
   │  ├─ onMinute = message.substring(separatorIndex + 1).toInt() // = 30
   │  ├─ onTriggered = false // Reset trigger flag
   │  ├─ String msg = "DA DAT LICH BAT: 14:30"
   │  └─ client.publish("nha_toi/binh_nong_lanh/trang_thai", msg.c_str())
   └─ Return

   Case C: Topic = "nha_toi/binh_nong_lanh/dat_lich_tat"
   ├─ Tương tự Case B
   ├─ Parse message thành offHour và offMinute
   ├─ offTriggered = false
   └─ Publish: "DA DAT LICH TAT: HH:MM"

5. KIỂM TRA LỊCH HẸN - checkSchedule()
---------------------------------------

   Bước 1: Lấy thời gian hiện tại
   ├─ int currentHour, currentMinute
   ├─ if (rtcAvailable):
   │  ├─ DateTime now = rtc.now()
   │  ├─ currentHour = now.hour()
   │  └─ currentMinute = now.minute()
   ├─ else:
   │  ├─ struct tm timeinfo
   │  ├─ if (!getLocalTime(&timeinfo)):
   │  │  └─ return // Không có thời gian, bỏ qua check
   │  ├─ currentHour = timeinfo.tm_hour
   │  └─ currentMinute = timeinfo.tm_min

   Bước 2: Kiểm tra lịch BẬT
   ├─ if (onHour != -1): // Có lịch bật
   │  ├─ if (currentHour == onHour && currentMinute == onMinute):
   │  │  ├─ if (!onTriggered): // Chưa trigger
   │  │  │  ├─ digitalWrite(relayPin, HIGH) // BẬT
   │  │  │  ├─ client.publish("...", "DA BAT THEO LICH")
   │  │  │  └─ onTriggered = true // Đánh dấu đã trigger
   │  │  └─ else: // Đã trigger rồi, không làm gì
   │  └─ else: // Không phải giờ này
   │     └─ onTriggered = false // Reset flag cho phút tiếp theo

   Bước 3: Kiểm tra lịch TẮT
   ├─ if (offHour != -1): // Có lịch tắt
   │  ├─ if (currentHour == offHour && currentMinute == offMinute):
   │  │  ├─ if (!offTriggered):
   │  │  │  ├─ digitalWrite(relayPin, LOW) // TẮT
   │  │  │  ├─ client.publish("...", "DA TAT THEO LICH")
   │  │  │  └─ offTriggered = true
   │  │  └─ else: // Đã trigger
   │  └─ else:
   │     └─ offTriggered = false // Reset flag

   Lưu ý về trigger flag:
   ├─ onTriggered/offTriggered ngăn việc trigger nhiều lần trong cùng 1 phút
   ├─ VD: 14:30:00, 14:30:15, 14:30:30, 14:30:45 - chỉ trigger 1 lần
   └─ Reset về false khi không còn match để sẵn sàng cho lần sau

KỊCH BẢN 1: BẬT/TẮT THỦ CÔNG
------------------------------

1. User mở Web Dashboard (http://localhost:3000)
2. Click nút "BẬT NGAY"
3. Frontend gọi POST /api/on
4. Backend publish: topic="nha_toi/binh_nong_lanh/lenh", msg="ON"
5. ESP32 nhận message qua callback()
6. ESP32 set GPIO 23 = HIGH (relay bật)
7. ESP32 publish: topic="nha_toi/binh_nong_lanh/trang_thai", msg="DA BAT"
8. Backend subscribe nhận "DA BAT", update lastStatus
9. Frontend polling GET /api/status mỗi 2s
10. UI cập nhật: "ĐANG BẬT" (màu xanh)

KỊCH BẢN 2: ĐẶT LỊCH
---------------------

1. User nhập: Giờ=14, Phút=30
2. Click "Đặt lịch BẬT"
3. Frontend gọi POST /api/schedule/on với body {hour: 14, minute: 30}
4. Backend publish: topic="nha_toi/binh_nong_lanh/dat_lich_bat", msg="14:30"
5. ESP32 nhận message, parse thành onHour=14, onMinute=30
6. ESP32 publish: "DA DAT LICH BAT: 14:30"
7. Backend update schedule.on = "14:30"
8. Frontend hiển thị: "Bật: 14:30 | Tắt: ---"

9. Khi đến 14:30:
   - loop() gọi checkSchedule()
   - Thời gian hiện tại (từ RTC hoặc NTP) = 14:30
   - checkSchedule() phát hiện match
   - Set GPIO 23 = HIGH
   - Publish: "DA BAT THEO LICH"
   - Set onTriggered = true (tránh trigger lặp lại)

KỊCH BẢN 3: MẤT KẾT NỐI
-------------------------

1. WiFi bị mất
2. ESP32 phát hiện !client.connected() trong loop()
3. Gọi reconnect()
4. Retry kết nối mỗi 5 giây
5. Khi WiFi trở lại:
   - Kết nối MQTT thành công
   - Subscribe lại tất cả topics
   - Tiếp tục hoạt động bình thường
